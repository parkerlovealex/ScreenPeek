# SEO & DEPLOY

## A. SEO rules

- **URLs:** lowercase keyword slugs, no IDs in public URLs (except collision suffix), trailing slash, canonical on every page (self-referencing; country variants share one canonical — geo changes content, not URL, except `/watch/` country switcher which uses `?country=GB` style links with canonical to the base).
- **Index gate:** only `quality_gate=1` titles appear in sitemaps, taxonomy listings' first pages, `/on/` pages and `similar` rails. Ungated detail pages render with `noindex` (they may still earn social traffic).
- **Sitemaps:** `/sitemap.xml` index → `sitemap-titles-1.xml…` (movies+tv, 10k URLs each), `sitemap-people.xml`, `sitemap-taxonomy.xml`, `sitemap-pages.xml`. Generated by a Function from D1 (cached 24h) — never static files. `lastmod` = title `updated_at`.
- **Meta:** title/description templates per ROUTES-AND-DESIGN copy rules; OG image = R2 w500 poster; Twitter card `summary_large_image` on detail, `summary` elsewhere.
- **Structured data:** JSON-LD `Movie`/`TVSeries` on detail (name, image, datePublished, genre — **NO `aggregateRating`**: never mark up third-party ratings; Google policy, manual-action risk), `Person` on cast pages, `TVEpisode` on episode rows/pages, `VideoObject` on trailer pages (YouTube embedUrl), `FAQPage` for the detail Q&A block, `BreadcrumbList`, `ItemList` on list pages.
- **Filter/sort URLs:** any URL carrying filter/sort query params gets `noindex,follow` + canonical to the clean list URL. Paginated clean URLs (`/page/2/` style or `?page=` if used) stay self-canonical and indexable.
- **Redirects & removals:** `redirects` table (admin SEO tab) is consulted before rendering → 301. Titles deleted by the owner return **410 Gone** (styled page). Unknown → 404 (logged to `notfound_log`, capped).
- **Share images:** detail OG image = the generated 1200×630 card (`og/<id>.jpg`, quality-gated titles only); fallback = w500 poster. Never rely on the tall poster for social shares (it crops badly on Telegram/X).
- **Originality:** detail pages carry the generated facts line + Q&A + "Updated" date (see ROUTES-AND-DESIGN) so no page is a bare copy of TMDb text.
- **Internal linking:** every detail links to: ≥1 genre page, its cast pages, similar titles, its watch page; home links Top 10 + latest; taxonomy pages paginate with crawlable `<a>` links (no JS pagination).
- **Robots:** allow all; disallow `/admin/`, `/go/`, `/api/`, `/search/`, `/mylist/`. Sitemap line included.
- **Performance as SEO:** the bandwidth budget (AGENTS.md rule 2) is also the Core Web Vitals strategy — keep LCP = poster image, CLS = 0 (reserved ad boxes, fixed image aspect ratios), INP trivial (almost no JS).

## B. Deploy — Cloudflare Pages + GitHub

### One-time setup (owner accounts; Codex prepares everything, owner clicks/authorises)

1. GitHub: create repo `movie-system`, push this package's repo (package files become repo docs; code is generated into the structure in ARCHITECTURE.md).
2. Cloudflare: create D1 database `movie-db` → apply `db/schema.sql` (`wrangler d1 execute movie-db --remote --file=db/schema.sql`). Create KV namespace `CONFIG`. Create R2 bucket `posters` and connect a **custom domain** (e.g. `img.<domain>`) with a Cache Rule / cache rule on the bucket responses: `Cache-Control: public, max-age=31536000, immutable`. (r2.dev is for the first local test only — it is rate-limited and must not ship to production.)
3. Cloudflare Pages: Create project → Connect to Git → select repo. Build settings: framework preset **Astro**, build command `npm run build`, output `dist`. Add bindings in Pages settings: D1 `DB`, KV `CONFIG`, R2 `POSTERS`. Env vars (production): see `templates/.env.example`.
4. Cloudflare Access: add a self-hosted application for `<domain>/admin/*`, policy = owner's email only.
5. GitHub Actions secrets for `sync.yml`: per SYNC.md env list.
6. First sync: run the workflow manually (Actions tab → Daily Sync → Run workflow), verify Dashboard counts, then let the schedule take over.
7. Custom domain (when bought): Pages → Custom domains → add; DNS on Cloudflare auto-configures; set `SITE_URL`.

### Environments

- Production = `main` branch. Preview deployments for other branches (Pages default) — verify changes there before merging. Ad codes: previews must render placeholders only (check `CF_PAGES_BRANCH` / env flag `ADS_ENABLED=0` on preview).

### Rollback

Pages keeps previous deployments — rollback from the Pages dashboard (Deployments → Rollback). D1 schema changes are additive-only in v1 (no destructive migrations without owner approval).
