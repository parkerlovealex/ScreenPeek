# Private backups (Phase 1)

`npm run backup:local` exports actual local D1 into an ignored, mode-0600 gzip archive under `.cache/backups/`, keeping 14. `npm run backup:run` is remote and refuses to run unless SCREENPEEK_BACKUP_ENABLED=1. The scheduled workflow defaults off and runs at 09:15 UTC only after owner setup.

The archive contains full application SQL plus config JSON. Environment/platform secrets are not inputs to the archive. Ad snippets, destinations, admin emails and audit data are sensitive: **use a separate PRIVATE R2 backup bucket**, never the public posters bucket or a bucket with an image custom domain. The constructor rejects the posters bucket and requires explicit BACKUP_BUCKET_PRIVATE=1. This flag records operator confirmation; it does not independently prove the bucket is private. Before enabling, verify public access and custom domains are disabled, then scope separate S3 credentials to this bucket. Store credentials in secure Actions settings.

R2 objects use application/gzip and private/no-store. A new upload must succeed before retention deletes old snapshots. Only recognised backups/ archive keys are eligible; unrelated objects are untouched. A truncated listing fails rather than dropping snapshots silently. Archives are not uploaded as public CI artifacts.

D1 export cannot dump FTS virtual tables. The job exports application tables (including migration records), excludes derived FTS/shadow tables and Cloudflare internal tables, then appends the schema and SQL to rebuild titles_fts from restored titles. This preserves searchable content without pretending the raw export supports FTS. The local archive is tested by restoring into a separate temporary D1 and comparing the title/FTS counts and config values. The SQL export is authoritative on restore; duplicated config JSON is captured before export and can differ if an owner edits config during the job.

Deployment verification deferred: create/verify the private bucket, enter scoped credentials, check the first scheduled archive and its access controls, confirm 14-snapshot retention, and repeat a restore drill against a separate non-production D1. No live bucket or account resource has been created or modified during development. Full SQL restoration into an existing production database needs an owner-reviewed import/rollback plan; do not run it automatically. Admin configuration restore is separately permission-gated and takes a pre-restore snapshot.

The Owner-only configuration restore accepts the manual JSON export (not a full SQL archive), requires the RESTORE confirmation, and writes a private compressed pre-restore snapshot through the BACKUPS binding before a guarded D1 batch. A storage failure prevents replacement. Imported links/ads/config are delivered in bounded, resumable KV batches; use Dashboard retry until delivery and purge finish. Deleted mirrors become disabled tombstones. Full SQL archive restoration is verified into a separate local D1, not exposed as a production overwrite button.
