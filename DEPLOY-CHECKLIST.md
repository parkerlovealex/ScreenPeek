# Deployment checklist

Target: **Cloudflare Workers with static assets**, D1, KV and R2. Pages commands in the supplied pack are superseded by the owner's approved hosting decision. No cloud resource, live sync, deployment, or Git push has been performed during local development.

Phase 1 is still in progress. Task 1.22 prepares deployment; final verification must be repeated after tasks 1.23–1.38. See `VERIFICATION.md` for current evidence and remaining checks.

- [ ] **Owner:** review the complete Phase 1 code and verification report before enabling remote workflows. Keep `SCREENPEEK_SYNC_ENABLED` and `SCREENPEEK_DEPLOY_ENABLED` unset meanwhile.
- [ ] **Owner:** use the existing GitHub repository `parkerlovealex/ScreenPeek`; review the local commits and arrange a push/PR. Require the CI checks before merging. GitHub-hosted CI has not run here.
- [ ] **Owner:** create/choose a Cloudflare account on the free plan. No paid plan or spending change is authorised by this checklist.
- [ ] **Owner:** create D1 `movie-db`, KV `CONFIG`, and R2 `posters`; record their IDs securely. Do not apply the development seed to remote D1.
- [ ] **Owner:** connect an owned R2 custom domain and set `R2_PUBLIC_BASE`. `r2.dev` is for local tests only. Custom-domain/image-header verification belongs to 1.26. Domain purchase remains deferred; no purchase is authorised here.
- [ ] **Owner:** choose the actual production Worker/custom-domain URL for `SITE_URL`. Set the current site name if different from ScreenPeek. The production preparer rejects the documented placeholder hostname.
- [ ] **Prepared locally:** run Node from `.node-version`, `npm ci`, `npm run db:setup`, typecheck and build. Local DB, seed and tests use `.wrangler/state` or isolated temporary state; no remote writes occur.
- [ ] **Prepared locally:** `npm run deploy:dry-run` validates the built Worker without deploying. Resource existence, token permissions and live bindings cannot be proven by this dry run.
- [ ] **Owner:** supply `CLOUDFLARE_ACCOUNT_ID`, `D1_DATABASE_ID`, `KV_NAMESPACE_ID`, `R2_BUCKET`, `SITE_URL`, and `R2_PUBLIC_BASE` through environment/Actions settings. `npm run deploy:prepare` writes these public binding settings only into ignored `dist/server/wrangler.json`. It does not create or deploy resources and does not embed API tokens.
- [ ] **Owner:** after preparing the production configuration, apply only the base schema and migrations remotely with the correct account/token: `node scripts/tool.mjs wrangler d1 execute DB --config dist/server/wrangler.json --remote --file db/schema.sql`, then `node scripts/tool.mjs wrangler d1 migrations apply DB --config dist/server/wrangler.json --remote`. Never run the seed/removal SQL with `--remote`.
- [ ] **Owner:** configure Cloudflare Access for both `/admin` and `/admin/*`, add the first lowercase owner email in `admin_users`, and enter Worker Access/purge/dispatch settings as described in [ADMIN-SETUP.md](docs/ADMIN-SETUP.md). Protect every reachable admin hostname. Secret values belong in encrypted Worker secrets; the deployment preserves platform variables not managed by the build.
- [ ] **Owner:** add Actions secrets: TMDb read token (or v3 key); Cloudflare account/deploy-sync token and D1/KV IDs; R2 S3 access/secret keys. Optional Telegram failure-alert credentials can remain unset. Add public Actions variables for site URL, image domain, bucket and site name.
- [ ] **Owner:** keep ad flag `ADS_ENABLED=0` on previews. Preview mode stays `DEPLOYMENT_ENV=preview`, noindex, disallow-all robots and empty sitemaps. Production preparation explicitly selects production indexing and defaults ads off; ads also require the admin master/slot switches and real placement codes.
- [ ] **Owner:** enter public contact details on Contact/DMCA and review the trust-page text in admin Pages. Public contact details remain unconfigured until supplied; no working contact form is claimed in Phase 1.
- [ ] **Owner:** enable only sync first (`SCREENPEEK_SYNC_ENABLED=1`); dispatch Daily sync with deployment unchecked. Verify at least 50 real titles, owned images, correct slugs, source quality gates, and a second run with zero duplicates. The daily schedule is **2:30 pm Bangladesh time**; GitHub can delay it.
- [ ] **Pending later Phase 1 tasks:** verify the nightly static tier, ≤15,000 files, long-tail SSR, speed gate, Lighthouse, custom image domain, originality/schema additions, redirects/404 logging, OG cards, full admin features and backups. Do not treat unfinished or blocked checks as passed.
- [ ] **Owner + final verification:** run every item from `prompts/phase1-build.md` on the completed build, then repeat live checks: admin-created redirect/click; test snippet placement/popunder cap/watch exclusion; vote/List persistence; real cache purge/Undo; sitemap/robots gates; 301/410/404 logging; image dimensions/cache headers; social cards; static/SSR and byte/Lighthouse gates. Record failures and unrun checks honestly.
- [ ] **Owner:** after reviewing the completed result, enable `SCREENPEEK_DEPLOY_ENABLED=1`. `npm run deploy` still refuses an incomplete Phase 1 checklist, missing credentials, placeholder resource IDs, or unsuitable production URLs. Scheduled runs may deploy only once enabled; manual dispatch must also select deployment. Do not enable this flag during the current incomplete phase.
- [ ] **Owner:** confirm live routes, footer/provider attribution, Access roles, cache behaviour and optional alerts after deployment. Keep Workers/D1/R2 usage under free limits and obtain approval before any paid change.
- [ ] **Owner:** retain a known-good Worker version and use the Cloudflare Workers deployments dashboard for rollback. Source schema changes remain additive; do not run destructive migrations or restore a backup without the required owner approval.

The current implementation uses approximate buffered counters as approved. Static pages take ad/content/settings changes on the next build; successful purge applies to cached SSR responses. A purge alone cannot rewrite static HTML.
